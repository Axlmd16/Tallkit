## Context

Plan técnico pendiente de revisión, elaborado después de [proposal.md](proposal.md) y [specs](specs/catalogo-visual-reutilizable/spec.md), conforme a la autorización conjunta de planificación de esta sesión. No autoriza implementación.

El checkout develop contiene React 19, TypeScript 6, Vite 8, Tailwind 4, Nunito local, Phosphor, React Router y TanStack Query. Las 24 exportaciones visuales de shared/ui conviven con estilos globales específicos de páginas. La arquitectura permite presentación genérica en shared/ui; el estado remoto pertenece a features y la composición funcional a app/pages. Se conservan ADR-0001/0002/0003, **Monolito modular**, sesiones y **Mismo origen**. Las fuentes documentales consultadas figuran en la propuesta.

## Goals / Non-Goals

**Objetivos:** 66 unidades de catálogo identificadas en la matriz, más un registro de tokens y una página de demostración de desarrollo. Una unidad puede ser una composición o reexportación; no exige 66 implementaciones independientes. Reutilización antes que duplicación; procedencia explícita por variante; pruebas **TDD** y comparación estructural/visual.

**No objetivos:** migrar páginas, sustituir el shell, cambiar login o formularios funcionales, introducir endpoints, modelos, datos, permisos o comportamiento de negocio. No implementar vistas semanales, drag-and-drop, editor enriquecido, cargas de archivos, notificaciones push ni servicios de chat a partir de un icono o etiqueta de Figma.

### 5. Aislamiento y contratos técnicos

La biblioteca usa módulos por familia y barrels aditivos, sin mover las importaciones públicas actuales. Clase1: reexportar desde ubicación existente. Clase2: props opcionales con defaults idénticos; fijar regresión de consumidores antes de modificarlos. Si exige cambiar un default, detener esa adopción y reservarla a la especificación de sustitución. Clase4 no autoriza reemplazar archivos o consumidores dentro de estas tareas.

Archivo futuro shared/ui/catalog-tokens.css y raíz data-visual-catalog. Reglas nuevas prefijadas por ese ámbito o clase exclusiva de componente; no redefinir :root, body, .app-rail, .list-page, .user-form ni .login-\* de la aplicación. No cambiar shared/styles/index.css para el catálogo: importar la base y añadir scope solo en entrada de demo. Las piezas no deben necesitar una clase users-page para funcionar.

Portales: portalContainer opcional y contenedor de demo con mismo scope/tokens; default existente conservado. Un envoltorio externo de Drawer no basta: hoy crea portal en document.body. Un mecanismo compartido de overlays debe coordinar bloqueo de scroll con contador, foco superior, fondo inert y restauración, probado con modal sobre drawer. Reutilizar la mecánica existente mediante extracción interna probada si hace falta, sin mantener implementaciones divergentes de foco ni cambiar resultados de defaults. Detalle persistente usa aside/section, nunca aria-modal. No reutilizar appearance confirm con sus assets excluidos.

Contratos:

- UI recibe children, label, value, selected, disabled y callbacks tipados; no importa features, hooks de sesión, clientes HTTP o modelos de negocio ni evalúa roles.
- Sidebar recibe items ya filtrados, activeId y onSelect. AppFrame recibe slots, sin Outlet o rutas reales.
- Field conserva contexto de id/error/ayuda. Select empieza nativo; no combobox remoto. Tabs asocia selección/panel; SegmentedControl usa selección exclusiva; menú implementa teclado correspondiente. Toolbar conserva modelo accesible de teclado.
- DataTable recibe columns/rows/key/selección/orden/callbacks; DataList reutiliza representación adaptable; paginación recibe números y callbacks, sin API. La selección mixta se anuncia.
- Gráficos: SVG calculado para datos genéricos suministrados, DOM para leyenda/tooltip y alternativa tabular. El SVG de series no se usa para fabricar iconos de Figma. Sin dependencia nueva de gráficos inicialmente: línea/área/anillo/barras son un repertorio acotado. Zoom o volúmenes masivos requieren otra decisión.
- Calendarios y cronograma: fecha/hora normalizadas y evento como bloque visual; selección/cambio de vista locales, sin recurrencia, reservas, asignación ni cálculo económico. Rejilla de selección con foco móvil por teclado; lectura con semántica tabular.
- Board y conversación no incluyen transporte. Indicadores/adjuntos son slots; no cargas ni mensajes reales. MediaSlot reserva geometría con superficie neutral, sin fotos ni ilustraciones nuevas.

Alternativas: Storybook añade runtime sin necesidad actual; se usa Vite existente. CSS global violaría aislamiento; se elige scope opt-in. Código absoluto de Figma pierde adaptación y semántica; grid/flex conserva geometría a tamaño nativo. Duplicar controles rompería mantenimiento; se prefieren composición y variantes.

No cambia ninguna frontera de dominio, persistencia o autenticación; no hace falta ADR nuevo para esta organización reversible. Si una dependencia o frontera cambia después, documentarla mediante ADR antes de aplicarla.

### 6. Página interna futura de demostración

Ubicación: frontend/src/dev/visual-catalog/, separada de pages/features; CatalogApp.tsx, registry.ts, fixtures.ts y ejemplos por familia. Entrada independiente frontend/visual-catalog.html y frontend/src/dev/visual-catalog/main.tsx, servida solo por Vite en desarrollo en /visual-catalog.html. Sin Route nuevo ni enlace en el shell. Navegación interna por hash con componente/variante/estado y controles de demo, sin API.

Build normal conserva exclusivamente index.html. Guard import.meta.env.DEV en entrada de demo; verificar que dist no contiene entrada, fixtures ni chunks de catálogo. El fallback SPA productivo para esa URL no debe montar la demo. No hay permisos nuevos: es herramienta de desarrollo, no ruta pública de negocio.

La galería tendrá índice y búsqueda local por familia/ID, ficha de procedencia, selector de variantes/estados, muestra corta/larga, reset determinista, paleta y escala tipográfica. Modo de aislamiento muestra solo la variante para capturar. Probar viewport real con Playwright: encoger un contenedor no prueba media queries.

Fixtures propios y explícitos: Elemento A/B, series técnicas, fechas fijas e iniciales abstractas; sin personas reales ni datos de Figma. Formulario corto/extenso son composiciones, no registro o autenticación. Ilustraciones omitidas; superficie neutral puede conservar su espacio.

## Migration Plan

Esta sesión agrega solo artefactos **OpenSpec**. No cambia specs principales ni declara aprobada la nueva capacidad.

Implementación posterior: aprobación y registro en master; revalidar inventario; demo aislada/tokens aditivos; lotes del catálogo; regresión de consumidores; revisión visual; sincronización documental y nueva spec en el momento autorizado del flujo.

No hay migración de datos, backend o API. Transacciones, concurrencia e idempotencia de negocio no aplican: no hay persistencia ni cálculos económicos. Las interacciones locales deben evitar callbacks duplicados mientras pending. No cambiar CSRF/sesiones/autorización.

Reversión futura: retirar archivos aditivos y entrada de catálogo; revertir solo variantes opt-in añadidas, manteniendo APIs previas. Sin datos o rutas que revertir. Otra especificación decidirá adopción por páginas y retirada de CSS específico.

## Open Questions

No hay preguntas técnicas rutinarias. Pendientes de revisión: adaptaciones tipográficas/accesibles, cuatro artefactos y futura aceptación visual. Revalidar nodos antes de cada lote; nuevas variantes de Figma requieren actualizar la procedencia. No se presume aprobación de valores no observados.
